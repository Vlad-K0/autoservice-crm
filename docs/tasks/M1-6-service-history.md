# Title: M1-6 История обслуживаний авто — эндпоинт-лента

---

**Этап:** M1 — Ядро CRM · **Модули:** `crm-clients` + `crm-api` · **Размер:** S · **Зависимости:** M1-2, M1-4

## Что делаем

«История заездов ведётся на уровне авто, а не клиента» — вывод (д) из обзора §3
(паттерн Dolibarr RAN / Odoo Fleet). Готовим контракт ленты и заглушку: наполняется
заказ-нарядами начиная с этапа 2.

**Эндпоинт:**

```
GET /api/vehicles/{id}/service-history
```

Ответ — единая лента событий (timeline):

```json
{
  "vehicleId": 42,
  "items": [
    {
      "date": "2026-11-06",
      "type": "WORK_ORDER",        // WORK_ORDER | APPOINTMENT | REMINDER (этапы 2, 3, 6)
      "refId": 17,
      "title": "Замена масла и фильтров",
      "mileage": 84500,
      "status": "COMPLETED",
      "amountMinor": 1250000       // сумма в копейках, см. ADR-0001
    }
  ]
}
```

На этом этапе `items` всегда пустой — важно зафиксировать **формат**, чтобы этап 2
просто начал его наполнять, а фронт (M1-F1) мог рисовать ленту уже сейчас.

## Готово, когда

- [ ] Контракт эндпоинта зафиксирован и задокументирован в Swagger
- [ ] 404 для несуществующего авто; пустая лента для существующего
- [ ] Тесты; `make test` зелёный

## Подсказки

- `type` — enum на будущее; сумму отдаём сразу в minor units (копейки), переучивать позже дороже.
- Ленту делаем именно по `vehicleId`, не по клиенту: клиент сменил авто — история авто осталась с авто.
