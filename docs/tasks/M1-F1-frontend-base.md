# Title: M1-F1 Фронтенд: каркас приложения и экран «Клиенты и авто»

---

**Этап:** M1 — Ядро CRM · **Слой:** `frontend` · **Размер:** M · **Зависимости:** M0-7 (ADR-0003), контракт из M1-4

## Что делаем

Первый вертикальный срез фронтенда по выбранному в ADR-0003 стеку.

**Каркас:**

- инициализация (Vite + TypeScript по ADR-0003);
- роутер и каркасная раскладка (сайдбар: Клиенты, Авто — дальше будут Календарь, Наряды, Склад);
- API-клиент, **сгенерированный из контракта** `docs/openapi/crm-api.yaml`
  (ADR-0004: `openapi-typescript` / `orval` — под ваш стек);
- до готовности бэкенда работа против мока: `make mock` → http://localhost:4010
  (Prism отдаёт сгенерированные данные по контракту, CORS включён).
- настройка dev-прокси на `localhost:8080`.

**Экран «Клиенты» (главный экран этапа):**

- таблица со поиском (строка поиска = `query` из M1-5) и пагинацией;
- форма создания/редактирования клиента (валидация зеркально бэку);
- карточка клиента: данные + список его авто + привязка авто.

**Экран «Авто» (если останется время — вынести в продолжение):**

- таблица с поиском (VIN/госномер/марка), карточка авто с лентой истории (M1-6, пока пустая).

## Готово, когда

- [ ] `npm run dev` поднимает фронт, работает против локального бэкенда
- [ ] Круговорот на реальных данных: создать клиента → привязать авто → найти по телефону/госномеру
- [ ] Ошибки бэкенда (400/404) показываются пользователю человеческим текстом
- [ ] README фронтенда: как запустить, как перегенерировать API-клиент
- [ ] CI собирает фронт (добавить job в `ci.yml`)

## Подсказки

- UI-кит берём из короткого списка ADR-0003 — не собирать таблицы руками, это 80% экранов CRM.
- Не делаем «свой красивый дизайн»: сейчас важнее скорость контура данные → экран.
