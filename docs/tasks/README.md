# Задачи в формате GitHub issue

Детальные формулировки задач для переноса в GitHub Issues / Projects.
Общий пул и статусы — в [../backlog.md](../backlog.md); здесь — готовые тексты.

## Как создать issue из файла

1. Открой файл задачи. **Заголовок** — строка после `# Title:`.
   **Тело** — всё, что ниже линии `---`.
2. В репозитории: Issues → New issue → вставь заголовок и тело.
3. Чекбоксы «Готово, когда» станут интерактивным чеклистом прогресса.

## Рекомендуемые labels

| Label | Когда вешать |
|---|---|
| `M0` … `M7` | этап из бэклога (совпадает с полем Этап на доске) |
| `backend` / `frontend` | сторона работы |
| `size:S` / `size:M` / `size:L` | размер из шапки задачи |

## План нумерации миграций Flyway

Чтобы параллельные ветки не конфликтовали на одинаковых `V<n>`:

| Миграция | Задача | Содержимое |
|---|---|---|
| `V2__clients.sql` | M1-1 | таблица `clients` |
| `V3__vehicles.sql` | M1-2 | таблица `vehicles` |
| `V4__ownership.sql` | M1-3 | `btree_gist` + `vehicle_ownership` с EXCLUDE |

Миграции живут в `backend/crm-api/src/main/resources/db/migration/`.
Новую миграцию в чужой файл — никогда (CONTRIBUTING).

## Разделение по слоям (напоминание из ADR-0002)

- Сущности/репозитории/сервисы домена → модуль `crm-clients` (`com.autoservice.crm.clients`).
- REST-контроллеры, DTO, security → `crm-api`.
- Междоменное — только через `crm-common` или интерфейс сервиса.
