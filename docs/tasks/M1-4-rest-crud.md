# Title: M1-4 REST API: CRUD клиентов и авто (контракт OpenAPI)

---

**Этап:** M1 — Ядро CRM · **Модули:** `crm-clients` + `crm-api` · **Размер:** M · **Зависимости:** M1-1, M1-2 (сущности и сервисы)

## Что делаем

Контроллеры и DTO в `crm-api`, бизнес-логика остаётся в `crm-clients`.
По нашему процессу — сначала фиксируем контракт (список ниже), потом реализация.

**Эндпоинты:**

```
POST   /api/clients                      создать клиента
GET    /api/clients?query=&page=&size=   список с пагинацией и поиском
GET    /api/clients/{id}                 карточка
PUT    /api/clients/{id}                 обновить
DELETE /api/clients/{id}                 удалить

POST   /api/clients/{id}/vehicles        привязать авто клиенту (период владения)
GET    /api/clients/{id}/vehicles        авто клиента (текущие)

POST   /api/vehicles                      создать авто
GET    /api/vehicles?query=&page=&size=   список
GET    /api/vehicles/{id}
PUT    /api/vehicles/{id}
DELETE /api/vehicles/{id}
```

**Что настроить:**

- DTO с валидацией (`jakarta.validation`: `@NotBlank` имя, `@Pattern` VIN, `@Size` госномер) — наружу никогда не отдаём JPA-сущности;
- единый формат ошибок — `ProblemDetail` (RFC 7807, Spring Boot 3 умеет из коробки): 404, 400-валидация, 409-конфликт;
- Swagger UI (`/swagger-ui.html`) показывает все эндпоинты — springdoc уже подключён.

## Готово, когда

- [ ] Контракт зафиксирован (этот список + Swagger) и не менялся по ходу
- [ ] Все эндпоинты работают: создан клиент → создано авто → привязано → читается в карточке клиента
- [ ] Ошибки в едином RFC 7807 формате, валидация возвращает 400 с деталями по полям
- [ ] Интеграционные тесты: happy path + 404 + 400 (`@SpringBootTest` + MockMvc/TestRestTemplate)
- [ ] `make test` зелёный, CI зелёный

## Подсказки

- DELETE клиента с историей — мягкое удаление (флаг `deleted`) или запрет с 409? Обсудить и записать решение в PR (потом станет ADR, если всплывёт ещё раз).
- Пагинация: `page` с 0 или с 1 — зафиксируйте в контракте сразу, фронт (M1-F1) будет опираться.
