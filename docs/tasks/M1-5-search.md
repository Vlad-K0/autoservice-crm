# Title: M1-5 Поиск по клиентам и автомобилям

---

**Этап:** M1 — Ядро CRM · **Модули:** `crm-clients` + `crm-api` · **Размер:** S · **Зависимости:** M1-4

## Что делаем

Поиск — главный ежедневный сценарий приёмщика: «звонит клиент / заехало авто →
найти за 2 секунды».VIN и госномер — ключевые ключи поиска (обзор §3, вывод (а)).

**Логика (заполняет параметр `query` из M1-4):**

- `/api/clients?query=`: совпадение по имени (ILIKE `%q%`), **точному телефону**, email.
  Телефон ищем по «хвостовому» совпадению — последние 4–10 цифр (`like '%79991234567'`),
  чтобы находило независимо от форматирования (+7, 8, пробелы).
- `/api/vehicles?query=`: точный VIN, точный нормализованный госномер,
  иначе ILIKE по `make || ' ' || model`.

**Технически:**

- нормализация входа: убрать из телефона всё, кроме цифр; госномер → upper без пробелов (как в M1-2);
- индексы уже есть (M1-2); при необходимости добавить индекс по `client_phones.phone`.

## Готово, когда

- [ ] Клиент находится по: части имени, точному телефону, хвосту телефона, email
- [ ] Авто находится по: VIN, госномеру, «марка модель»
- [ ] Пустой `query` = обычный список с пагинацией (не ошибка)
- [ ] Тесты на каждый тип поиска; `make test` зелёный

## Подсказки

- Если ILIKE по имени начнёт тормозить (данных пока мало — не начнёт), оптимизация — pg_trgm + GIN-индекс; записать как идею в этап 7.
