# ADR-0002: Монорепо и модульная структура

- **Статус:** принято
- **Дата:** 2026-11-06

## Контекст

Двое разрабатывают параллельно, по доменам (вертикальные срезы).
Домены определены в обзоре:
[docs/research/oss-crm-survey.md](../research/oss-crm-survey.md) (§3–4).

## Решение

- Монорепо: `backend/` + `frontend/` + `docs/`.
- Backend — Maven multi-module; **модули = домены**, не технические слои.
- `crm-api` — единственная точка сборки: `main()`, контроллеры, security.
  Доменные модули — обычные jar-библиотеки.
- `crm-common` — только код, нужный трём и более модулям (деньги, аудит).
- Версии зависимостей — в `<dependencyManagement>` родительского POM.
- Стек фронтенда — отдельное решение (ADR-0003, пока не принято).

## Последствия

- Параллельная работа без конфликтов; границы модулей видны в POM.
- Требуется дисциплина: домен не лезет в чужие таблицы и пакеты; междоменные
  зависимости — через `crm-common` или интерфейс сервиса.

## Альтернативы (отклонены)

- Два репозитория (backend + frontend) — сложнее синхронизировать контракты.
- Модули по техническим слоям (dao/service/web) — оба разработчика
  конфликтуют в одних папках, зоны ответственности размыты.
